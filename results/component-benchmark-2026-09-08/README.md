围绕“能否找齐来源”和“能否找回用户历史”分别测量两个组件。公开完整数据集、运行脚本、冻结协议、真实 API 记录及离线复算入口。

## 从问题到数据

**RAG 为什么不是所有问题都放进“可回答”分母？** 400 条查询中，340 条有明确目标来源，40 条用于测试无答案过滤，20 条是不提供必要历史的上下文对照。三者分别统计。开发集 80 条、测试集 320 条按来源和场景族划分，测试集的召回分母为 272；同一来源的中英文改写不会跨划分。

**Mem0 如何独立测试？** 直接运行冻结的记忆组件，对每个虚构用户写入两次会话，重开存储后查询；评分核对返回的个人事实。测试集有 96 个场景，两个问题共 192 次正向查询；另外执行 288 次无答案及作用域检查。

RAG 以“问题标注的每组来源至少命中一项”为完整覆盖；Mem0 以“每个预设个人事实均得到召回记忆支持”为语义覆盖。两套指标按各自分母解释。
