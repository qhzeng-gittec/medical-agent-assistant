# Mem0：120 个跨会话个人记忆场景

本测评独立执行冻结的[记忆组件实现](../../../medix-agent-swarm/evals/component_benchmark_v2/runtime/long_term.py)：**Mem0 OSS 2.0.20 + 本地 Qdrant**。Qwen3.5-27B 通过真实 API 从虚构用户的两次会话中抽取记忆，Qwen3-Embedding-8B 负责嵌入；关闭并重新打开存储后，再执行个人历史查询。

共 **120 个场景、240 次正向历史查询**：开发集 24 场景 / 48 查询，冻结测试集 96 场景 / 192 查询。每个场景另含未知用户、其他应用和同主题无答案检查各一次。场景是独立统计单位，同一场景的两个问题不增加场景数量。

## Top 3 / Top 10 的事实覆盖

固定同一批实际召回记录和阈值 0.3，只改变提供给评分器的候选数量。以下为冻结测试集结果：

| 配置 | 所有预期事实均有记忆支持 | 字面锚点全部命中 |
| --- | ---: | ---: |
| Top 3 | 176/192（91.7%） | 111/192（57.8%） |
| Top 10 | 184/192（95.8%） | 114/192（59.4%） |

Top 3 → Top 10 的全部事实支持率变化为 **+4.2 个百分点**。语义支持按问题预设的事实逐项判断，人物、时间、否定和确定性须一致；全部事实均得到支持才计该问题通过。

字面锚点是另一项严格文本匹配指标：每组至少出现一个预写的同义短语。它便于离线核对，但同义改写、数字表达和语序变化会影响命中，因此与语义支持分开报告。

## 持久化与查询作用域

| 检查 | 冻结测试集结果 | 如何执行 |
| --- | ---: | --- |
| 存储重开后查询 | 96/96 场景完成 | 写入两次会话，关闭后重新创建客户端，再进行 192 次正向查询；内容质量见上表 |
| 未知用户查询为空 | 96/96 | 同一存储内，换用未写入过的用户 ID，使用相同问题查询 |
| 其他应用查询为空 | 96/96 | 保持用户 ID，切换 app_id 后查询 |
| 同主题未披露信息查询为空 | Top 3：0/96；Top 10：0/96 | 在历史问题后询问未提供的门诊发票编号，检查阈值 0.3 下是否返回空集 |

无答案项测量相似度过滤的行为。返回相关历史材料时，后续回答环节仍需核对用户所问的具体事实是否在材料中。

## 怎么构建、怎么评分

1. 为 12 类记忆需求各构造 10 个虚构场景，每场景包含两次会话和两个历史问题；用户可能在第二次会话补充、否定或更正先前陈述。
2. 预先写出问题的预期事实与词汇锚点，由 MiniMax M2.5 辅助复核后冻结数据。开发集与测试集按场景分开，Top 3 / Top 10 与阈值 0.3 在运行前固定。
3. 各场景从独立空存储开始，执行真实抽取与嵌入。通过项目的密集向量检索接口收集 Top 10，保留记忆正文、分数、源会话和记录时间。
4. MiniMax M2.5 根据召回内容逐项判断预期事实。评分输入保留源会话顺序和记录时间，支持结论须引用实际返回的记忆；程序附上该条完整原文并校验引用 ID。相同问题、事实和候选集合只评分一次。
5. 汇总全部 120 个完成场景，开发集和测试集分别统计。公开逐项评分和原文引用，可用标准库脚本复算计数；模型辅助评分用于个人事实检索评估。

| 场景类别 | 开发场景 | 测试场景 |
| --- | ---: | ---: |
| 工作作息与睡眠时间变化 | 2 | 8 |
| 运动限制与日常活动 | 2 | 8 |
| 药物过敏及具体反应 | 2 | 8 |
| 用户和家人的经历区分 | 2 | 8 |
| 确诊与待检查的不确定性区分 | 2 | 8 |
| 按医嘱停用药物的时间线 | 2 | 8 |
| 预约复查与检查准备安排 | 2 | 8 |
| 搬家旅行与生活环境变化 | 2 | 8 |
| 用户更正先前陈述 | 2 | 8 |
| 饮食偏好与个人生活习惯 | 2 | 8 |
| 多项历史事实的跨会话汇总 | 2 | 8 |
| 否定事实与助手建议区分 | 2 | 8 |

开发集的全部事实支持数为 Top 3 **41/48**、Top 10 **44/48**；详细词汇与作用域指标见机器可读汇总。
