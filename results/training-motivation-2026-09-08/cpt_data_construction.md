# 现有 CPT 是否按任务关键词从大量医学资料中构建

**部分是，但还没有达到“系统检索相关资料并确认所需知识覆盖”的目标。** 当前实现是针对待补题的关键词/TF-IDF/BM25段落检索，保留少量候选，再用既有背景资料补足训练预算。新增语料构建与训练尚未执行；本次完成代码、实际产物核查和6组关键词检索可行性检查。

## 1. 实际执行过的构建过程

1. 对全部6,435条项目记录（train 5,418、validation 503、test 514）做已有资料复用盘点，包含知识、病例、上下文与VQA四类。
2. 从待进一步检查队列中选出1,353道文字题：315道知识、1,038道病例。新增大语料检索仅面向这个队列，并非重新逐一检索全部6,435条。
3. 检索使用题面、解释和目标答案，TF-IDF加权分别为0.35、0.45、0.20；FTS5/BM25使用最多14个一般词、6个答案锚点及低频词组合。没有显式医学同义词、缩写展开。
4. 教材与StatPearls稀疏检索先选30个候选，FTS每查询每来源最多16个候选，局部排序后每题保留5个段落。候选原文进入构建器；这不是所有命中文档，也未恢复完整章节或文章上下文。
5. 将检索段落、已审查材料、已有研究上下文加入，再用原先背景语料补足约800万医学token，另混入约1%通用回放。最终训练总量8,081,502 token。

可核对代码：[检索](../../MediX-R1/experiments/mine_cpt_sources.py)、[查询字段](../../MediX-R1/evaluation/audit_cpt_reuse.py)、[构建器](../../MediX-R1/data_processing/prepare_cpt_expanded_candidate.py)。实际状态及源文件哈希见[cpt_audit.json](cpt_audit.json)。

| 核查项 | 实际结果 | 意义 |
| --- | --- | --- |
| 新检索时使用的资料 | 教材125,847段、StatPearls355,180段，共481,027段 | 已有大规模本地词法检索基础 |
| 候选检索 | 1,353题均有候选；新增检索摘要记录4题已有语义审查 | “有候选”不是“所需事实完整覆盖”；4题只指这条新增检索链，不是整个项目全部审核数 |
| 针对性证据 | 1,354,871 token，占训练总量16.8% | 包含上下文等不同材料，不是每题关键事实曝光量 |
| 背景填充 | 6,645,608 token，占82.2% | 训练数据大部分来自背景填充 |
| 通用回放 | 81,023 token，占1.0% | 与医学证据分开 |
| 来源进一步复算 | WikiDoc共5,136,102 token，占总量63.6% | 名为背景指南的桶不能理解成全部是现行官方指南 |
| 测试题候选映射 | 知识45/150，病例95/162，上下文97/97，VQA 0/105 | 是显式关联记录；未映射不等于未覆盖，已映射不等于充分支持 |
| 最终语义覆盖 | manifest为false；全覆盖门禁未通过 | 此次已训练的是探索候选语料，不能宣称已验证全覆盖 |

旧代码在遇到重复正文时直接返回，关联记录可能没有保留第二道题到同一文档的链接。因此映射数还可能受到去重方式影响，不能把45/150直接当作知识覆盖率。下一版应将“文档去重”和“题目—文档多对多映射”分开。

背景中已有121份PubMed来源材料、455,540 token；**未进入这轮训练的是后来下载的大规模MedRAG/PubMed候选库，不是完全没有PubMed来源文本。**

## 2. 海量资料检索能否做得更完整

可以沿用现有本地索引实现，不需要先换成向量检索或生成大量新文本。目前索引快照共11,351,792条记录：教材125,847、StatPearls355,180、PubMed 10,870,765。

PubMed下载状态是失败，已完成651/1,167个计划文件，索引也有651份输入。失败日志为下载临时文件缺失；本次没有重新下载，不能把该索引叫全量PubMed。旧的等待全量下载后再挖掘任务也已失败，不能假设后台仍会自动完成。

还要区分资料形态：本地MedRAG/PubMed说明将`content`定义为论文摘要；MedRAG教材已切成不超过约1,000字符的片段。因此检索百万级记录并不等于取得百万篇论文全文。可在来源明确的前提下恢复教材相邻段、StatPearls章节；需要全文时另获取可用正文并记录版本。

本次用6组来自既有诊断主题的手选关键词，分别查询三个现有索引，每来源保留最多5条用于检查。全部6组至少在一个来源有候选，其中StatPearls六组均有候选；另有教材和PubMed查询零命中，保留原结果。[实际查询、标题、来源ID与正文哈希](retrieval_feasibility.json)

这些只是检索可行性探针，**没有进行模型训练，也没有认证候选语义正确、足以解题或符合最新规则**。不同来源可能补充召回，但不能从6组推导总体覆盖率。

## 3. 更接近目标的下一版构建方式

| 环节 | 具体处理 | 需要留下的证据 |
| --- | --- | --- |
| 明确目标 | 逐条处理训练/开发题；旧test如参与选材则标为诊断，保留另一个不参与选材的新测试集 | source_id、split、task、选材用途 |
| 提取查询 | 从题面、经核对的解释和参考答案提取实体、关系、条件；对药名、缩写和同义词展开，保留否定、数值和人群限定 | 原始关键词、别名、关系和查询式；生成关键词不得取代来源证据 |
| 广泛找候选 | 继续用BM25/词法检索，多查询合并；对未覆盖事实扩大候选，避免每题固定5段即结束 | 每来源候选、排名、查询与索引版本；零命中也保留 |
| 恢复必要上下文 | 检索定位后按章节、相邻段或可用正文恢复语境，去掉无关章节与噪声 | 文档/章节ID、范围、原文哈希；避免把整本教材或整篇长文全部加入 |
| 审查关系覆盖 | 判断是否明确支持所需实体关系、方向、条件和例外，标记完整/部分/未定位/冲突 | 原子事实→证据原句→出处；关键词命中分数不能自动判为覆盖 |
| 清理与预算 | 核对版本和冲突、去重；共享文档保留全部题目关联；按事实与学科平衡曝光，不用背景自动补满预算 | 去重记录、多对多映射、来源占比、每事实曝光次数 |
| 进入CPT | 使用核验的医学原文，分块时保留完整关系及必要上下文，检查实际token位置 | 事实→文档范围→训练块与token范围；仅有文档文件不算完成曝光 |

这里的目标是**广泛检索后筛出真正支持任务知识的资料**。只把命中常见病名的所有文档都纳入，可能引入大量无关研究、旧定义或重复背景；检索范围可以大，进入训练的内容仍应由证据质量、覆盖与预算决定。图像特有判断和研究上下文特有结论分别处理，不能用文字CPT覆盖率替代视觉能力或上下文理解。

事实改写、双向问答、反例监督可以另设实验组，但应标为合成事实训练或SFT，不混称为纯原文CPT。[领域/任务适配预训练](https://aclanthology.org/2020.acl-main.740/)支持研究任务相关选材；[Synthetic continued pretraining](https://arxiv.org/abs/2409.07431)研究多种数据表达对知识获取的作用。两者都是方法依据，不能替代本项目的效果对照。

## 4. 何时才值得扩大训练

先固定训练与评分协议，核对数据、token和训练链路，再比较：直接SFT、普通医学语料CPT→相同SFT、任务相关检索语料CPT→相同SFT。两个CPT组匹配有效训练token、模型起点、优化配置和预算；它们相对直接SFT增加的成本单独报告。

正式确认至少使用500个独立题目或事实，按知识/病例等任务分层，测试题不用于选材和调参。主要指标为最终闭卷答案及跨问法稳定正确性，报告改对、改错、原有能力保持和不确定性；效果小时按所需精度扩样。旧错题修复单独报告，不以事后挑出的错题代表总体泛化。

只有更准确的选材在相同后续SFT下带来可靠净收益，才扩大语料。若只降低文本loss而答题没有改善，继续区分事实曝光、问答调用、数据冲突及后续训练干扰。**当前完成的是诊断发布与构建可行性核查，不是新CPT已训练成功。**
