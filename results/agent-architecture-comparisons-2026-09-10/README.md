# Agent 架构与任务覆盖对照 · 2026-09-10

本报告公开两组受控 Agent 实验：第一组比较单 Agent、额外复核和多 Agent 架构；第二组比较连续复核单 Agent与独立分工多 Agent在多事项核对任务上的覆盖、错误、耗时和输入 token。两组均运行真实模型和工具协议，但使用合成资料，不是临床准确率评测。

## 实验在比较什么

项目的总控 Agent 可以将任务交给健康咨询、诊断和医学研究三个专业助手。增加分工会带来额外的规划和汇总调用，因此我们分别测量答案质量和运行开销。

第一组让助手检索模拟资料，回答简单查询、多问题核对或带适用条件的问题。四种方案含义如下；“实验旧版”指运行时冻结的版本，不代表 GitHub 当前代码。

| 方案名称 | 如何完成一次任务 |
| --- | --- |
| 普通单 Agent | 同一个助手使用全部业务工具并回答 |
| 单 Agent 加复核 | 单助手先生成初稿，再检查完整过程并修改答案 |
| 实验旧版多 Agent | 总控按需要调用专业助手，再汇总回答；当时限制同轮同专业的重复调用 |
| 独立任务多 Agent | 放开上述限制，允许同一专业分别处理不同任务 |

第二组测试多事项核对：从模拟患者记录及给定规则中生成待办清单，核对事项是否属于正确的人、日期及适用条件。**连续复核单 Agent**在同一对话中依次检查三个方向后合并；**独立分工多 Agent**让专业助手在各自上下文中检查相关资料，再汇总。“固定分工”是后续候选，由程序直接启动三个核对任务。这些分工候选属于评测原型。

一份清单可能包含多个事项。“覆盖率”是必要事项找全的比例，“精确率”是输出事项中正确的比例，“完整正确”要求整份清单既无漏项也无错项。表中的输入 token 表示模型累计读取的文本量，模型请求数表示累计调用次数。

## 结果概览

| 实验 | 数据与对照 | 关键结果 |
| --- | --- | --- |
| 四种 Agent 架构 | 12 个场景，每种方案重复 2 次，共 96 次主执行；另有 12 次串行消融 | 实验旧版多 Agent 与普通单 Agent 的严格通过分别为 **17/24、18/24**；平均耗时 **77.19、49.15 秒**。实验定位并复现了 9 次“同专业不同任务”误拒绝，候选实现降为 0 次 |
| 多事项任务覆盖 | 32 道同题对照、898 个标准事项；连续复核单 Agent 与独立分工多 Agent 各执行 32 次 | 两组完整正确均为 **13/32**；分工方案平均耗时 **119.8→70.3 秒（−41.3%）**，输入 token **2,486,128→627,044（−74.8%）** |
| 固定分工补测 | 8 道新题，两种方案各执行 8 次 | 完整正确 **2/8→3/8**，平均耗时 **160.7→37.8 秒**；样本小且对照有两次未交付，单独作为机制补测 |

适合由这些结果支持的结论是：专业分工可以改变任务拆解方式，并在需要连续多轮核对的工作流中减少重复输入和总耗时；现有数据没有把这种效率收益等同于稳定的回答质量提升。

## 实验一：四种架构与串行消融

四种主方案均使用 MiniMax M2.5、相同资料包和七个业务工具：

| 方案 | 严格通过 / 计划 | 有效双评 | 平均耗时 | 模型费用 / 次 | 模型请求 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通单 Agent | 18/24 | 21/24 | 49.15 秒 | $0.00285 | 73 |
| 单 Agent 加复核 | 15/24 | 20/24 | 81.21 秒 | $0.00560 | 107 |
| 实验旧版多 Agent | 17/24 | 22/24 | 77.19 秒 | $0.00546 | 125 |
| 独立任务多 Agent | 19/24 | 21/24 | 81.23 秒 | $0.00629 | 139 |

每个方案在 12 个场景上重复 2 次。场景覆盖简单查询、多项独立问题、较长资料包和有条件依赖四类任务。Qwen3.5-27B 与 MiniMax M2.5 按冻结检查项匿名双评；任一适用检查项未获两票通过，则该次运行不计严格通过。

实验旧版多 Agent 的 24 次主执行没有出现 Worker 并发，并在 T08、T09、T11 共拒绝 9 个同专业但任务不同的调用。独立任务候选把误拒绝降为 0，并在 3/24 次运行中实际并发。这验证了调度限制及修复行为；候选的质量分数还受到小样本、12 份无效评分和已定位的评审错误影响，因此不作为质量提升结论。

预先选定的 6 个场景各重复 2 次进行候选并行/串行消融：并行版严格通过 11/12、平均 86.09 秒，串行版 8/12、69.18 秒。两组虽然模型请求总数都为 65，但模型重新规划后任务图和调用分布不同，不能把差值解释成固定工作量下的纯并发因果效应。

## 实验二：多事项覆盖与输入成本

主要比较合并两批共 32 道新题。题目要求从带时间和主体信息的资料中形成核对清单，共有 898 个“患者—事项”标准要求。所有方案使用相同 MiniMax M2.5、冻结输入和输出上限；程序根据可见文档中的事项 ID 计算覆盖率、精确率和整份清单是否完全正确。

| 方案 | 完整正确 | 平均覆盖率 | 平均精确率 | 平均耗时 | 输入 token | 模型请求 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 连续复核单 Agent | 13/32 | 84.4% | 74.5% | 119.8 秒 | 2,486,128 | 279 |
| 独立分工多 Agent | 13/32 | 78.7% | 74.1% | 70.3 秒 | 627,044 | 177 |

分工方案在 24/32 道题中实际并发，输入 token 减少 74.8%，平均耗时减少 41.3%。两组各有未交付或格式无效运行；只看双方均正常交付的 22 对答案，分工方案覆盖率差为 −0.28 个百分点，95% 区间 `[−3.87, +2.94]`。因此效率结果应限定为相对“连续多轮复核单 Agent”的完整流程对照。

固定分工候选另在 8 道冻结新题上补测，用于确认由程序直接启动三个专业核对任务能否避免主管未委派。该方案 8/8 交付，对照为 6/8；样本不足以支持稳定质量结论，未合并进 32 题主结果。
