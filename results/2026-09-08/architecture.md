# Agent 架构与并发测评

这里分别回答两个问题：固定子任务并行是否省时，以及当前多 Agent 完整流程相比单 Agent 的耗时与成本如何。两者计时范围不同，分别报告。

## 固定任务：并行省下多少时间

固定诊断、问诊、研究三个 Worker 任务，使用真实 MiniMax M2.5 和工具，只切换串行/并行执行方式。各测 3 次、交替顺序，期间不运行其他本次评测任务。计时从批次启动到最后一个 Worker 返回，排除总控规划与最终汇总。

| 指标 | 串行 | 并行 |
| --- | ---: | ---: |
| 三次耗时（秒） | 56.64、42.58、50.19 | 22.47、13.86、24.11 |
| 平均耗时（秒） | 49.80 | 20.15 |
| 模型请求总数 | 22 | 20 |
| 输出 Token 总数 | 4,349 | 5,213 |
| 最大实际 Worker 并发数 | 1 | 3 |

按未四舍五入的均值计算，耗时缩短 `(49.802 − 20.1457) / 49.802 = 59.5%`，加速倍数为 **2.47**。三次重复不足以消除云端负载和生成长度波动，该结果仅支持固定子任务阶段的并发收益。

## 完整案例：多 Agent 的编排成本

8 个开发场景，两架构各重复 2 次，共 32 组执行，全部获得最终回答。均使用真实 MiniMax M2.5、相同温度、患者档案、上下文与基础工具；使用真实查询 embedding 和 15 文档本地向量索引，没有在线 Mem0、外部搜索或本项目微调模型。

| 指标 | 单 Agent（16 组） | 多 Agent（16 组） |
| --- | ---: | ---: |
| 平均案例耗时（秒） | 17.82 | 37.05 |
| 案例耗时中位数（秒） | 10.29 | 11.43 |
| 模型请求总数 | 33 | 89 |
| 模型与检索费用（美元） | 0.0168 | 0.0522 |
| 供应商连接或请求错误数 | 0 | 2 |
| 已完成自动质量评分的执行数 | 8 | 9 |

完整流程包含总控、Worker、工具、汇总以及实际错误处理开销。多 Agent 平均耗时为单 Agent 的 **2.08 倍**，本次没有测出端到端提速。自然任务中出现 4 个多 Worker 同轮批次，最大并发为 3；并非每个问题都会触发三个 Worker。

质量使用 Qwen3.5-27B 匿名逐项评审，17/32 完成后因服务余额不足中断；已有评分也有需复核项，因此不计算或宣称准确率提升。费用为本批供应商记录的模型与检索观测值，不是当前报价或质量评分预算。

## 对照条件与适用范围

单 Agent 可直接使用全部 7 个底层工具、允许并行工具调用，最多 10 轮模型迭代、24 次工具调用。多 Agent 使用当前配置：最多 4 轮总控、每次 Worker 最多 2 次工具调用。角色提示、上下文隔离和推理预算属于两套实现的差异，所以完整案例对照衡量这套具体配置的成本，不能将差异单独归因于“Agent 数量”。

每组执行使用隔离进程，执行先后顺序平衡，同时最多运行两组案例。主表保留出现服务错误的运行，避免只挑顺利案例。没有额外训练种子或大样本显著性结论。
