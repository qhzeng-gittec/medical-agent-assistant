# 当前 Agent：设计与 72 场景整体测评

本页展示多轮迭代后保留的 Agent 设计，以及当前版本在完整问诊、历史记忆和证据使用任务上的表现。评测执行实际的 Supervisor、三个专业 Agent、患者档案、工具和记忆流程，逐轮保存回答与状态。

## 关键设计

| 设计 | 解决的问题与实现选择 | 实现及验证入口 |
| --- | --- | --- |
| 语义调度与专业分工 | 总控结合问题、状态和已有结果决定委派；独立任务同轮并行，有依赖的任务分轮执行。三个 Worker 只注册各自职责内的 Skills | [总控](../../medix-agent-swarm/swarm/supervisor_agent.py)、[注册与调度测试](../../medix-agent-swarm/tests/test_supervisor_agent.py) |
| 分层记忆与上下文预算 | 稳定事实存患者档案，近期对话保留完整轮次并受字符预算约束，跨会话事件由 Mem0 检索；避免将全部历史塞进每次调用 | [近期对话预算](../../medix-agent-swarm/memory/context_budget.py)、[预算测试](../../medix-agent-swarm/tests/test_context_budget.py) |

总控先完成同轮档案/历史操作，再把更新后的上下文交给 Worker；最后按实际返回证据汇总答复。专业 Agent 的分析、用户原话和检索文档分别保留，便于追溯答案依据。RAG 是其中的证据来源之一。

## 整体结果

**被测模型：Qwen3.5-27B。** 总控和 Worker 均使用这一模型、temperature=0.2。**评分模型：MiniMax M2.5 与 Qwen3.5-27B**，两者按冻结检查项独立评审；评分输入隐藏被测版本标识。相同模型同时参与生成与一位评审，因此结果按模型辅助评测解读。

| 能力 | 场景数 | 执行完成 | 有效双评 | 全部适用检查项通过 |
| --- | ---: | ---: | ---: | ---: |
| 多轮问诊与咨询 | 24 | 24 | 23 | 21/24 |
| 病史与跨会话记忆 | 24 | 24 | 24 | 23/24 |
| 证据检索与使用 | 24 | 24 | 24 | 23/24 |
| **合计** | **72** | **72** | **71** | **67/72（93.1%）** |

“通过”要求两位评审对全部适用项均判通过；只有双方均判不适用的项才排除。71 场有有效双评，其中 67 场全项通过、4 场未全项通过；另 1 场评分错误保留在 72 场计划分母中。此处发布最终版本的单次回归表现，不估计迭代带来的增益。

## 场景与运行方法

场景来自已有的合成测试集，每类包含常规、复杂、边界各 8 个。它们在先前迭代中已使用，属于历史回归；HH-014 也参与最近一轮开发。每场运行一次，72 个场景不等于 72 个独立临床病例。

每个场景预先定义首问、后续提问、可披露的患者事实、历史输入和逐项要求。运行器只在对应交互时点提供信息，完整场景数据和未来脚本不会一次性交给被测模型。检查同时查看回答、实际工具返回、前后档案及记忆记录；写出“已保存”本身不构成成功。

每场使用独立进程和存储，总控最多 4 轮、Worker 最多 5 轮，工具调用次数开放，Worker 超时 120 秒，单轮对话超时 600 秒。连接建立最多尝试三次，读取超时不重发；无效评分按同一请求最多补试一次，有效判分不重评。公开原始评分与补评记录。

28 场运行真实本地 Mem0 OSS，2 场使用受控历史池；其余关闭或不需要长期记忆。RAG 有 20 场使用固定证据、1 场实际调用 embedding 检索冻结语料，另有空结果和超时场景各 1 场。该组主要衡量 Agent 如何使用信息和完成任务；检索排序见单独的 [RAG 数据集与测评](../../medix-agent-swarm/evals/hybrid_grounding_v3/README.md)。

例如 HH-001：用户在首轮说明佩戴助听器及偏好文字沟通，换会话后要求为新门诊整理接诊说明。检查要求系统利用实际保存的个人信息，保留用户自述性质，并避免补出未提供的检查结果。完整输入、回答和双评可在 [逐场结果](case_results.json)中按 `HH-001` 查找。

## 运行观测与工程验证

72 场合计提出 **365 次工具请求**、执行 **195 次检索后端调用**；工具上下文记录 **46 次正文加入、96 次文档引用加入**。含预置历史处理的场景耗时中位数为 **84.8 秒**。这些是本次运行的观测计数，不能把引用次数直接当作节省的请求数。[机器汇总](summary.json)

另外已通过 **104 项 Agent 自动测试和 48 项评测运行器测试**，检查路由、档案作用域、上下文预算、证据复用、存储重开与协议处理。工程测试使用确定性网络输出，与上表真实 API 场景评测分别统计。
